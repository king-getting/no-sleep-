# 小山 · 开发任务分工清单

> 前提：主体架构已落地（契约类型层 / 编排器 / 4 Agent / 本地数据层 / 三餐报告 UI / 编排事件流 / PWA）。
> 本清单是「从架构到完整 MVP」的全部剩余工作，按 §14.1 分工：**A 管引擎（逻辑与数据），B 管体验（界面与路演）**。
> 读码顺序：先读 `docs/agent-contract.md`（v1.1 变更记录必读），再读 `src/types/contract.ts`，再动各自目录。

## 协同纪律（复习 §14.2）

- 分支：`feat/*` 进 PR；时间紧可直推 main，但 commit 必须走约定式提交（`feat:` / `fix:` / `docs:` / `chore:`）
- 契约变更 = 双方确认 + `docs(contract): …`
- B 开发一律先用 `src/mock-orchestrator.ts` 的固定 JSON，A 的真实接口就绪后只换数据源，渲染代码不动
- mock 数据集中在 `src/data/mock/`，UI 禁止直连假数据（走 adapter / 契约 Schema）
- 每日两次对齐（午间 + 晚间各 15 分钟），阻塞不过夜

## A · 引擎任务（`src/agents/` `src/orchestrator/` `src/data/`）

### A1. 修复冲突主张触发逻辑 ✅ 已完成（2026-10-21）
- 最终规则（预警与主张分离，对应设计文档两条独立规则）：
  - §4.2 风险预警（稀缺）：48h 内有 DDL **且** 之前没有 ≥2h 整块空档 → warning「没有整块复习时间」；`hasFreeBlockBefore` 已修正为从 now 起算、过期时段不计
  - §5.3 冲突主张（争夺）：48h 内有 DDL **且** 今晚（18:00–23:00）存在 ≥2h 整块空档 → 主张该空档用于复习，与健康 Agent 的「提前睡」构成 L2 真冲突
- 验收：周三 11:30 午间报告**有**冲突卡（今晚有空档 + DDL 40h 后 + 近三天缺觉三方齐备），但**无**「复习窗口紧张」假预警；21:30 晚间报告无冲突卡（今晚剩余空档 <2h，争夺战不成立）
- ⚠️ 注意：本清单初版验收标准「周三应无冲突卡」有误——那会砍掉路演最高潮的冲突演示，以上述最终规则为准

### A2. 编排器依据富化（evidence enrichment）✅ 已完成（2026-10-21）
- 已实现：`src/orchestrator/enrich.ts`，汇总阶段按规则表把跨域 Finding 挂载到选项卡（新规则 = RULES 加一行）；`life.ts` 已不再 import 睡眠模块

### A3. 课表 / 考试手动录入的数据层 ✅ 已完成（2026-10-21）
- 已实现：Dexie v2 新增 `courses` / `exams` 表；`src/data/store/courses.ts` 提供 `listCourses/addCourse/updateCourse/deleteCourse` 与 `listExams/addExam/updateExam/deleteExam`；`src/data/queries.ts` 全部改读库（取数函数异步化，纯函数保持同步）
- 种子与升级：首启填充示例课表/考试；示例模式下每次启动刷新示例考试（DDL 演示永不过期）；v1 老库自动补种课表
- 验收：B 侧用 `addCourse()` / `addExam()` 录入后，晨间报告内容随之变化 ✅ 已实测（库内 courses 13 条 / exams 3 条）

### A4. 睡眠手动录入接口 ✅ 已完成（2026-10-21）
- 已实现：`upsertSleepLog(log)` / `deleteSleepLog(date)`（`src/data/store/profile.ts`），同一日期覆盖写
- 验收：录入昨晚 7.5h 后，健康 Agent 的午间小憩建议不再出现 ✅ 已实测（小憩与 L1 合并卡消失，睡眠恢复后冲突卡按规则也不再出现）

### A5. 本地定时触发器
- 页面打开 / 到点（7:30、11:30、21:30）自动生成对应报告；跨天时启动补生成
- 注意：PWA 关页后无法真定时，路演讲稿按「本地定时 + 手动唤出」口径
- 验收：把系统时间/触发参数调到 11:30，午间报告无需点按钮即出现

### A6. 生存模式引擎（§4.8 MVP 裁剪版）
- `mode` 判定：考前 7 天自动进入 `exam`，全部结束自动退出
- 复习计划生成规则：掌握度差优先排整块、记忆类插碎片；每晚复盘后动态重排
- Agent 权重动态调整记录进事件流（供 B 做动画展示）
- 验收：录入 3 天后的考试 → 晨间报告变「冲刺报告」；考后自动生成小结数据

### A7. 信息流相关性打分
- 在 adapter 身份过滤之上加打分（年级/校区/学院标签匹配度 + 「与我无关」负反馈降权）；负反馈落库
- 验收：同一条通知对「大二/计算机/桂子山」与「研一/南湖」排序不同；点「与我无关」后同类沉底

### A8. 遵从度回流扩展
- 现状只有小憩降级消费了 `compliance`；扩展到：连续未执行的建议类自动降优先级、周报告统计遵从度
- 验收：同一建议连续 2 次「没做」→ 第三次出现时 priority 降一级

### A9. 部署与演示保障
- Vercel 部署（`npm run build` 产物即静态站）；断网演示彩排清单（build + preview 下验证，dev 模式 SW 不注册）
- 验收：线上 URL 可访问；preview 下关 WiFi 刷新页面功能照常

## B · 体验任务（`src/ui/` `src/pages/` + 路演素材）

### B1. Onboarding 流程（§4.9）⭐ 产品故事第一屏，最高优先
- 第 0 屏隐私承诺「所有数据只存在这台设备上」→ 身份（本科/研究生→年级→学院）→ 身体基线（知情选填，标注不填的代价）→ 课表导入（手动/示例填充/可跳过）→ 餐标设定 → 偏好快问快答 3 题 → 收尾「个人画像卡」
- 数据落库走 A3/A4 的接口；未就绪前用 mock-orchestrator 驱动页面开发
- 验收：新用户 30 秒走完；每步可跳过（身份除外）；画像卡正确回显全部录入

### B2. 首页「今日校园」信息流（§4.1）
- 卡片流 + 每条「为什么推给我」标注 + 收藏 /「与我无关」按钮
- 验收：三类源（教务/讲座/生活服务）混排展示；负反馈后刷新仍生效

### B3. 「我的这一周」时间轴视图（§4.2）
- 时间块色块视图（上课/整块/碎片三色），风险项置顶标红
- 验收：周三视图能看到早八连排与「午休被吃掉」标红

### B4. 复习计划草案 + 拖拽调整
- 依赖 A6 的计划数据；草案卡片可拖拽换序/换时段
- 验收：拖动「高数复习 2h」到另一空档，重排结果落库

### B5. 晚间报告闭环交互（§4.6/§4.7）
- 「做了 / 没做」一键标记 → `markCompliance()`；点「没做」出归因选项（起晚了/不饿/没时间/忘了）
- 措辞中性，无红叉；任何追踪可一键「不再追问」
- 验收：标记后遵从度画像更新（可在设置页看到）

### B6. 健康模块 UI
- 睡眠手动录入表单；一周睡眠/精力趋势周报卡（`recharts` 已在依赖里）
- 验收：录入后趋势图更新；缺觉日在图上有视觉区分

### B7. 设置页
- Agent 逐个启停（改注册表 `enabled`）、餐标修改、示例数据一键清除（`clearAllData()` 已备好）、LLM API Key 选填入口
- 验收：关掉健康 Agent 后报告不再含健康建议；清除数据后回到 onboarding

### B8. 编排动画视觉升级版 ⭐ 演示抓手
- 现状：文字时间线（`src/ui/animation/OrchestrationTimeline.tsx`）；升级成「总控拆任务 → 4 Agent 并行 → 冲突检出 → 汇总成卡」的大屏动画
- 只订阅事件流（契约 §6），不得 import 引擎内部
- 验收：路演投屏时 10 秒内能看懂多 Agent 协同全过程

### B9. 暗色模式
- 跟随系统（`prefers-color-scheme`）切换 `.dark` class；变量已配好
- 验收：系统切深色后全站跟随，对比度可读

### B10. 生存模式 UI
- 冲刺报告样式、考前夜保底睡眠冲突卡（A/B 选项：按计划睡 / 再看 1h 且代价写清）、考试日物品清单卡、考后小结卡

### B11. 路演素材
